# ADR-021: Read-only Streamlit results explorer as an optional dependency group

**Status:** Accepted (engineering decision, 2026-10-16, from the dashboard specification)

## Context

The engine produces raw JSONL, `run.json`, `summary.csv`, a report and plots. A reviewer should be able to explore a recorded run without installing anything beyond a browser, and the app should be hostable on Streamlit Community Cloud.

## Alternatives considered

A static HTML report only (no interactivity); a dashboard that can launch benchmarks (unsafe on a public host and not reproducible); Streamlit as a core dependency (pulls pandas/pyarrow-class packages into the engine, against ADR-013).

## Decision

`sdplab.dashboard` is a read-only viewer in a `dashboard` dependency group (`streamlit>=1.66,<2`; pandas and Altair arrive transitively). `[tool.uv] default-groups = ["dev", "dashboard"]` makes plain `uv sync` include it; `uv sync --no-group dashboard` gives the engine only, and the dashboard tests then skip. Only `dashboard/app.py` imports Streamlit; `discovery.py` and `data.py` are testable without a browser. The app reuses the engine's own checks (`results.validate_run`, `analysis.summarize`) and cross-checks `summary.csv` against a recomputation. It reads only direct, non-symlink children of one results root (`results/examples` or `SDPLAB_RESULTS_DIR`), only whitelisted file names, with size caps; it has no uploads, no free-text path input and never runs a benchmark. Errors are shown as short messages with absolute paths scrubbed. "Fastest" and "smallest" statements are always scoped to an operation, size and run, with an IQR-overlap caveat.

## Consequences / trade-offs

The default environment is larger (48 locked packages). Streamlit Community Cloud's handling of uv dependency groups is not verified here (see `deployment.md` for the fallback). Streamlit does not hot-reload the editable `sdplab` package; restart the server after engine or dashboard-module edits.
