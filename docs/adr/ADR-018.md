# ADR-018: Workers prime lazy imports and first-call paths before the timer

**Status:** Accepted (engineering decision, 2026-10-15)

## Context

Each trial runs in a fresh process, so lazy imports (for example `zipfile` inside `np.load` of an `.npz`) and first-call code paths are paid inside the timed region. In a first smoke run `npz` load at 2,000 rows measured about 3 ms in a fresh worker versus about 0.34 ms after priming (single-machine observation), i.e. the gap was module import, not data work. ADR-004 says start-up and imports are excluded from the timed region.

## Alternatives considered

No priming (measure everything a one-shot process pays); run the operation twice in-process and time the second (changes cache and allocation state of the data under test).

## Decision

Before the memory baseline and the timer, the worker runs the same operation once on a separate tiny array (8 rows) through the same variant, then deletes the tiny file. Every trial record carries `measurement.primed_imports = true`. The tiny file is separate from the data under test, so it does not warm the page cache for it.

## Consequences / trade-offs

Timings exclude module-import and first-call cost; a one-shot CLI user would still pay that cost once. Documented in the README limitations.
