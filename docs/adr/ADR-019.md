# ADR-019: Phase 3 design points settled: worker input, loop order, prepare vs timed write

**Status:** Accepted (engineering decisions, 2026-10-15; these were deferred to Phase 3 by the user)

## Context

Worker input for `write`/`preprocess`, scheduling loop order, and the conflict between an untimed `prepare` write and the timed worker `write` (PROPOSAL sections 5 and 9) were left open.

## Alternatives considered

Read a canonical file for `write`/`preprocess` input; sizes-outer loop; time the write inside `prepare`.

## Decision

(1) `write` and `preprocess` regenerate the dataset from `(rows, seed)` with `dataset.generate` inside the worker as untimed setup; expected hashes and the preprocess digest come from the `prepare` job. (2) Rounds-outer: every round contains every (size, variant, operation) cell once in a seeded shuffled order, so thermal and background drift is spread across sizes and variants. (3) `prepare` is an untimed worker job that writes the canonical files and validates them; the only timed write is the worker `write` operation, which targets a scratch directory and is verified by an untimed read-back. (4) `preprocess` runs once per size on in-memory data under the variant name `in_memory`. (5) Memory counters: `VmHWM` is reset (`/proc/self/clear_refs`, best effort, recorded as `hwm_reset`) after setup so it reflects the timed region.

## Consequences / trade-offs

A round at 10^6 rows needs all sizes' files on disk at once (about 160 MB); a round is long, so interrupted runs lose the partially measured round only.
