# ADR-007: Strict exact-equality correctness contract

**Status:** Accepted (reaffirmed 2026-10-13)

## Context

CSV text float round-trip is a known hazard; silent corruption would invalidate timings.

## Alternatives considered

`allclose` tolerance; CSV-specific tolerance.

## Decision

Identical dtype, shape and bytes/SHA-256 for every loaded array, plus identical preprocess outputs. If a variant fails, investigate writer, parser and schema first and document the cause; the contract changes only through a new ADR with justification.

## Consequences / trade-offs

Strict; CSV may need investigation (risk R1). `np.array_equal` alone is insufficient (it treats 0.0 and -0.0 as equal), so bytes/hash is the gate.
